 paging.c:
    paging_init():
        Error/Bug:
            1. Data structure of struct union struct was not being recognized and could
                not be accessed.
            2. Data structure was being accessed but a different implementation was 
                preventing access utilizing the old method.
            3. First page directory address was ambiguous and not correct with tests. 
            4. Kernel address needed (0x400000) was too big to shove into the 4mb page
                directory implementation.
            5. Page table address for page_table[0xB8] was set to 0x8B000. Caused unwanted
                issues within the code.
            6. Page table addresses for ones not being used (for CP1) were set to 0.
            7. Paging was causing the OS window to bootloop.
            8. Paging was causing the OS window to crash.
            9. Paging was reviewing by multiple TAs and they all could not figure out the   
                issue that was the culprit.

        Fix:
            1. Ptr arguments were added to paging_init() to allow access to the structs.
            2. Ptr arguments were removed and used struct calling conventions to access
                and edit elements.
            3. Set the value of the address as the start of the page_table array. Works
                because an array is a set of ptrs (addresses).
            4. Kernel address needed was split between the two address bit spaces dedicated
                for the structure.
            5. Page table address for page_table[0xB8] was set to 0xB8.
            6. Page table addresses for ones not being used (for CP1) were set to the index 
                value.
            7. Changed structures to rid of the indexing ([i][j]).
            8. Changed other things BUT caused the OS window to crash again.
            9. Completely redid the implementation of paging. For example, the union structs
                were rid of, but the variable initializations were set as the same as before.

 sys_call_asm.S:
    syscall_handler:
        Error/Bug:
            1. General protection error was called.

        Fix:
            1. Extra layer of assembly linkage was pushing extraneous content to the stack
                so altered to not alter stack.

 sys_call.c:
    execute:
        Error/Bug:
            1. Ran into the issue where it would spin cycles after context switching. 
            2. Invalid commands would repeat the last valid executed command.
            3. Page fault when a command larger than 32 chars was entered into shell.
            4. Boot loop occurred when starting the OS.
            5. Execution's assembly was not working. Caused various issues/errors.
            6. Execution could be prone to interrupts by the system call.

        Fix:
            1. Did not re-enable interrupts so an sti() was added.
            2. Execute did not account for the return error inside of read_dentry_by_name
                ,and as a result did not recognize the invalid command.
            3. Added a conditional to return -1 when encountering a command that exceeded
                the buffer's size.
            4. Discovered esp0's value was set incorrectly. Changed to correct value.
            5. Switched to inline assembly to bypass various issues/errors.
            6. Wrapped a majority of exeuction with cli() and sti() to prevent interuptions.

    halt:
        Error/Bug:
            1. Unexpected halt of shell when a process was complete.

        Fix:
            1. Altered the PCB's esp/ebp to the current processes rather than the parent PCB's 
                esp/ebp.

 paging.c:
    paging_set_up:
        Error/Bug:
            1. Page fault occurs when setting up the 8MB pages.
            2. Page faults were occuring when executing different processes.
            3. Page faults were still occuring after FIX 1.
            
        Fix:
            1. Page directory's base address was not shifted by 22 for alignment.
            2. TLB was not being flushed.
            3. Global bit of paging was set to 0 to allow TLB to flush.
